# S4: Windowed balance reconciliation (L3) and data volume (Polkadot Asset Hub)

- **Run:** `pnpm --filter @potluck/spikes s4` (window size via `S4_WINDOW`, default 1200)
- **Raw output:** [`s4-balance-reconciliation.json`](./s4-balance-reconciliation.json)
- **Measured:** 2026-10-20 (three runs; the last one is recorded in the JSON)

## Part A: reconciliation (the L3 premise)
For a window of 1,200 recent finalized blocks (single runtime, spec 2005000), every `Balances.*` event was decoded with the executing runtime and mapped to a delta on **total = free + reserved**. Then, for **every** touched account:

`total(B) − total(A−1) == Σ deltas in [A, B]`

| Run | Delta rows | Accounts checked | Reconciled |
|---|---|---|---|
| final | 811 | 319 | **319 / 319 (100%)** |
| previous | 820 | 319 | 319 / 319 |

Delta rules on `free + reserved`. All 30 `Balances` event variants are classified; no unknown variant appeared.

| Effect | Events |
|---|---|
| `−account` | `Withdraw`, `Slashed`, `Burned`, `BurnedHeld`, `Suspended`, `DustLost` |
| `+account` | `Deposit`, `Minted`, `Restored` |
| `−source / +dest` | `Transfer`, `ReserveRepatriated`, `TransferOnHold`, `TransferAndHold` |
| 0 (internal move or no account) | `Endowed` (always accompanies the funding event), `Reserved`, `Unreserved`, `Held`, `Released`, `Locked`, `Unlocked`, `Frozen`, `Thawed`, `Upgraded`, `Issued`, `Rescinded`, `MintedCredit`, `BurnedDebt`, `TotalIssuanceForced` |
| Absolute (not reconcilable by deltas, reported separately) | `BalanceSet` (none occurred) |
| Flag as unknown | `Unexpected` |

**Bug found and fixed during the spike:** `toJSON()` on an `AccountId` yields an SS58 string. Building the `System.Account` key from it silently reads an empty account (27/333 "reconciled"). Canonical rows must take accounts as **hex AccountId32 via `toHex()`**, which is now a rule for `core`.

## Implications
- **The L3 verification design holds.** Reconciliation is exact for 100% of real accounts with a complete, closed rule table. Verification cost per account per chunk is 2 storage reads.
- **The earlier ~250 MB assumption was wrong by 2.5–4×.** Publishing the whole Revive window as one MVP job (~0.6–1 GB on a shared testnet, ~12 h of RPC) is too heavy for the MVP. See the decision in `docs/ARCHITECTURE.md` §15.
- Most volume is per-transaction fee plumbing (`Deposit`/`Withdraw`). Encoding optimizations (per-chunk account dictionary, columnar layout) are P1. The chunk format keeps NDJSON+gzip for the MVP.
