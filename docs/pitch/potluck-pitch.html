The idea

Potluck

Index once, store it on Portaldot, verify it everywhere.

01 · PUBLISH

Anyone indexes

A publisher runs a declarative JSON spec against a source chain's archive RPC, now and then. Output: canonical NDJSON chunks, identical on every machine.

Who: anyone with the CLI and a little POT. Not an always-on server.

02 · STORE

Portaldot keeps it

Chunks go into TransactionStorage, where validators must keep proving they hold the data. A manifest is registered in PotluckRegistry on pallet-revive.

Who: Portaldot validators. Paid once, read by anyone for free.

03 · VERIFY

The browser checks

The dApp fetches only the chunks it needs over the node's bitswap_v1_get, checks them against the source chain, then live-tails new blocks.

Who: the user's own browser. No API key, no backend.

Snapshots are only an accelerator. With no manifest, the SDK syncs straight from the source chain: slower, never blocked.

Verification

Three levels, checked in the browser

Trust the source chain, not the publisher.

L1

Integrity

Digest, raw hash, canonical encoding, bloom. Catches corrupted or swapped chunks.

L2

Row truth

Each row re-derived from its block's events on the source chain. Catches invented or altered rows.

L3

Reconciliation

Balance before + every row's effect = balance after, for every account and window. Catches hidden rows, even with every hash forged.

Attack demo · Pantry

A forged chunk hides one transfer and recomputes every hash.

Built on V3

WASM/EVM compatibility · modular · multi-chain

One product, every V3 primitive.

TransactionStorage

  • Chunks, specs and manifests stored on-chain; fees measured on testnet
  • Blobs fetched by CID with bitswap_v1_get from the public node: 2.5 MB in ≈ 4 s

pallet-revive, both VMs

  • PotluckRegistry.sol: one source, solc → EVM (deployed) and resolc → PVM (dry run passes)
  • Identical ABI, so the client does not care which VM serves it

Two-VM history for Portaldot

  • Native transfers + Revive ERC-20/721 logs in one index
  • SS58 ↔ H160 from the ReviveApi runtime API; 14 ↔ 18 decimals handled

Multi-chain sources

  • Polkadot AH, Kusama AH and Portaldot V3 through one spec format
  • Every block decoded with the runtime that executed it (≥ 35 Polkadot AH runtimes)
Adaptive sync. Direct when cheap (Portaldot today), verified snapshots when not. When Portaldot gets busy, its dApps switch over with no code changes.
